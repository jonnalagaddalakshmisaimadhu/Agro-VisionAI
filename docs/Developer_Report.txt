1. EXECUTIVE SUMMARY & PLATFORM OVERVIEW
----------------------------------------------------------------------------------------------------
Agro-VisionAI (branded in-app as "FarmIQ AI Agro") is an end-to-end agritech enterprise platform
designed to empower Indian and global farmers with cutting-edge artificial intelligence, real-time
telemetry, agronomic insights, financial modeling, and peer-to-peer commerce.

The system addresses the critical pain points of modern agriculture:
1. Early Crop Disease Identification: Rapid on-field diagnosis of 39 leaf disease categories via a
   210 MB Convolutional Neural Network and Gemini multimodal fallbacks.
2. Intelligent Crop & Soil Advisory: Location-based soil prediction via KNN geospatial models, combined
   with real-time weather and IoT soil moisture data to generate high-profit crop recommendations.
3. Market Transparency & Agmarknet Mandi Integration: Real-time price tracking across Indian mandis,
   price change trends, and customizable price alerts.
4. End-to-End Agri-Commerce: Direct peer-to-peer marketplace for produce, grains, and fruits, plus an
   equipment rental sharing economy platform (tractors, tillers, harvesters).
5. Government Subsidy & Scheme Aggregation: Curated database of Central & State schemes with automated
   background refresh schedulers and direct application links.
6. Aquaculture Hub: Dedicated marine and inland fisheries module featuring water telemetry monitoring
   (pH, Dissolved Oxygen, Temperature), feed calculators, and species management.
7. Real-Time Farmer Community & Tele-Agronomy: Live WebSocket-based multi-room community discussion
   and video consultation booking with agricultural experts.

4. BACKEND ARCHITECTURE & REST/WEBSOCKET API REFERENCE (FastAPI)
----------------------------------------------------------------------------------------------------
The backend is built with FastAPI and runs on Uvicorn. It mounts static file directories (`/models` and
`/uploads`), configures CORS for local development and Firebase production domains, initializes database
schemas automatically via `Base.metadata.create_all(bind=engine)`, and manages background lifespans.

CORE ROUTER & ENDPOINT REFERENCE:

1. Authentication (`/api/auth`) - [app/routers/auth.py]
   • POST `/api/auth/register` : Creates new user account, hashes password using bcrypt.
   • POST `/api/auth/login`    : Validates credentials, returns JWT bearer access token (HS256).
   • GET  `/api/auth/me`       : Returns current authenticated user profile (requires Bearer token).
   • PUT  `/api/auth/me`       : Updates user farm size, phone, location, and bio.

2. Disease Detection (`/api/disease`) - [app/routers/disease_detection.py]
   • POST `/api/disease/predict`      : Accepts base64 leaf image. Runs local PyTorch CNN (or Gemini fallback),
                                        saves image to `uploads/detections/`, extracts 5-point diagnosis via
                                        Groq LLaMA 3.3, and records result in `disease_detections` table.
   • POST `/api/disease/predict-test` : Test alias for health checks and automated validation.
   • GET  `/api/disease/detections`   : Fetches past disease scan history for the authenticated user.
   • GET  `/api/disease/detections/{id}`: Retrieves individual diagnosis details.

3. Crop Recommendation (`/api/crops`) - [app/routers/crop_recommendation.py]
   • POST `/api/crops/recommend` : Ingests farm parameters (location, farm_size, soil_type, season, budget,
                                   previous_crop) + live Open-Meteo IoT data (temperature, humidity, soil_temp,
                                   soil_moisture). Queries Groq LLaMA-3-8B to generate 6 precision crop options
                                   complete with financial yield, investment, duration, price trend, and net ROI.

4. Weather & Forecast (`/api/weather`) - [app/routers/weather.py]
   • GET `/api/weather/current`    : Current temperature, humidity, wind, pressure from OpenWeatherMap.
   • GET `/api/weather/forecast`   : 5-day / 3-hour meteorological forecast for farming planning.
   • GET `/api/weather/advice`     : Agronomic operational suitability index (planting, spraying, irrigation).
   • GET `/api/weather/coordinates`: Geocoding lookup translating city names to lat/lon.

5. Market Prices & Mandi (`/api/market-prices`) - [app/routers/market_prices.py]
   • GET  `/api/market-prices/prices`        : Active mandi commodity prices with category/location filters.
   • GET  `/api/market-prices/prices/trends` : Price movement percentage and direction over 7 to 30 days.
   • GET  `/api/market-prices/history`       : Historical 6-month price trends for dashboard Recharts visualizer.
   • POST `/api/market-prices/alerts`        : Creates custom price threshold alerts (above/below target price).
   • POST `/api/market-prices/refresh`       : Triggers manual live fetch from Agmarknet API.

6. Produce Marketplace (`/api/marketplace`) - [app/routers/marketplace.py]
   • GET    `/api/marketplace/products`     : Browse agricultural products with category, location & organic filter.
   • POST   `/api/marketplace/products`     : Create produce listing (seller_id extracted from JWT).
   • GET    `/api/marketplace/products/{id}`: Detailed product specifications.
   • PUT    `/api/marketplace/products/{id}`: Update stock, price or description (owner-only).
   • DELETE `/api/marketplace/products/{id}`: Remove listing.

7. Farm Machinery Rental (`/api/equipment`) - [app/routers/equipment.py]
   • GET  `/api/equipment/equipment`        : Browse available machinery (tractors, harvesters, tillers, pumps).
   • POST `/api/equipment/equipment`        : List equipment for rental with daily/hourly pricing.
   • GET  `/api/equipment/equipment/{id}`   : Equipment specifications, features, and owner details.
   • POST `/api/equipment/rentals`          : Initiate equipment booking with date range and cost calculation.
   • GET  `/api/equipment/rentals/my-rentals`: View active, pending, and past equipment bookings.

8. Government Schemes (`/api/schemes`) - [app/routers/government_schemes.py]
   • GET  `/api/schemes/`             : Filter schemes by category (Subsidy, Credit, Insurance), state, or crop.
   • GET  `/api/schemes/schemes/{id}` : Scheme details, required documents, eligibility, and official apply URL.
   • POST `/api/schemes/apply`        : Submit in-app scheme assistance application.
   • POST `/api/schemes/refresh`      : Background trigger to sync with national agriculture portals.

9. Profit & Loss Estimator (`/api/profit`) - [app/routers/profit.py]
   • POST `/api/profit/predict` : Calculates gross revenue, input costs (seeds, fertilizer, labor), and net profit
                                  per hectare using live mandi prices or regional averages.

10. Soil KNN & District Geocoding (`/api/predict-soil` & `/api/soil`) - [app/routers/soil_knn.py]
    • POST `/api/predict-soil` : Ingests `{ lat, lon }`. Runs Scikit-learn KNN model over coordinates in radians
                                 or falls back to Haversine nearest-neighbor lookup across 700+ Indian districts.
    • GET  `/api/soil`         : District-level fallback endpoint.

11. Conversational Chatbot (`/api/chat`) - [app/routers/chatbot.py]
    • POST `/api/chat` : Multi-turn dialogue endpoint powered by Async Groq (LLaMA-3.1-8B-instant) with dedicated
                         agronomic system instructions.

12. Real-Time Community Chat WebSocket (`/api/community`) - [app/routers/community_chat.py]
    • WS `/api/community/ws/{community_id}` : Multi-channel real-time WebSocket connection manager broadcasting
                                              messages across connected peer farmer sessions.

5. DATABASE ARCHITECTURE (Dual SQLite/PostgreSQL ORM + MongoDB NoSQL)
----------------------------------------------------------------------------------------------------
The platform utilizes a hybrid database approach:

A. Relational Layer (SQLAlchemy ORM):
Default engine connects to `sqlite:///./farmiq.db` (configured to seamlessly switch to PostgreSQL via `DATABASE_URL`).
Key Tables & Schema Definitions:
• `users`: `id`, `username`, `email`, `password_hash`, `full_name`, `phone`, `location`, `farm_size`,
           `is_active`, `is_verified`, `bio`, `profile_image`, `preferred_language`, `created_at`
• `disease_detections`: `id`, `user_id` (FK), `crop_type`, `image_path`, `disease_name`, `confidence_score`,
                        `severity`, `symptoms` (JSON), `treatment` (JSON), `prevention` (JSON), `is_verified`,
                        `expert_comment`, `created_at`
• `crop_recommendations`: `id`, `user_id` (FK), `location`, `soil_type`, `farm_size`, `budget`, `season`,
                          `previous_crop`, `recommended_crops` (JSON), `weather_data` (JSON), `created_at`
• `products`: `id`, `name`, `description`, `category`, `price_per_unit`, `unit`, `stock_quantity`,
              `seller_id` (FK), `location`, `is_organic`, `is_verified`, `rating`, `image_url`

6. MACHINE LEARNING, DEEP LEARNING & AI ENGINES
----------------------------------------------------------------------------------------------------
Agro-VisionAI combines localized neural networks with cutting-edge Large Language Models:

6.1 PyTorch 39-Class Plant Disease CNN (`plant_disease_model_1_latest.pt` - 210 MB):
• Architecture (`Backend/models/CNN.py`):
  - 4 Convolutional Stages:
    * Stage 1: Conv2D(3->32, k=3, p=1) -> ReLU -> BatchNorm2D(32) -> Conv2D(32->32) -> ReLU -> BatchNorm -> MaxPool(2)
    * Stage 2: Conv2D(32->64, k=3, p=1) -> ReLU -> BatchNorm2D(64) -> Conv2D(64->64) -> ReLU -> BatchNorm -> MaxPool(2)
    * Stage 3: Conv2D(64->128, k=3, p=1) -> ReLU -> BatchNorm2D(128) -> Conv2D(128->128) -> ReLU -> BatchNorm -> MaxPool(2)
    * Stage 4: Conv2D(128->256, k=3, p=1) -> ReLU -> BatchNorm2D(256) -> Conv2D(256->256) -> ReLU -> BatchNorm -> MaxPool(2)
  - Dense Classifier:
    * Flatten to 50,176 dimensions -> Dropout(0.4) -> Linear(50176, 1024) -> ReLU -> Dropout(0.4) -> Linear(1024, 39)
• Input Preprocessing: Resize to 224x224 RGB, ToTensor normalization.
• Supported Classes (39 Categories):
  Apple (Scab, Black rot, Cedar apple rust, Healthy), Blueberry (Healthy), Cherry (Powdery mildew, Healthy),
  Corn (Cercospora leaf spot, Common rust, Northern Leaf Blight, Healthy), Grape (Black rot, Esca/Black Measles,
  Leaf blight, Healthy), Orange (Citrus greening/Huanglongbing), Peach (Bacterial spot, Healthy),
  Pepper Bell (Bacterial spot, Healthy), Potato (Early blight, Late blight, Healthy), Raspberry (Healthy),
  Soybean (Healthy), Squash (Powdery mildew), Strawberry (Leaf scorch, Healthy),
  Tomato (Bacterial spot, Early blight, Late blight, Leaf Mold, Septoria leaf spot, Spider mites, Target Spot,
  Yellow Leaf Curl Virus, Mosaic virus, Healthy), Background without leaves.

6.2 Groq LLaMA 3.3 70B & 3.1 8B Diagnostic Engine (`groq_service.py` & `chatbot.py`):
• Disease Deep Analysis: When a disease is detected, `groq_service.py` sends the classified disease label and
  confidence score to `llama-3.3-70b-versatile` with JSON Mode enabled.
• Exact 5-Point Rule: Formats structured botanical analysis returning exactly 5 bullet points for Symptoms,
  5 bullet points for Treatments, and 5 bullet points for Preventions.
• Real-Time Conversational Assistance: `chatbot.py` utilizes `llama-3.1-8b-instant` for sub-second, multi-turn
  agricultural Q&A.

6.3 Google Gemini 1.5 Flash Vision & Fallback Multimodal Intelligence:
• Client & Server Multimodal Backup: In environments where PyTorch is not available or when analyzing novel
  unseen crop species, the platform invokes Google Gemini 1.5 Flash (`gemini-1.5-flash-latest`) directly
  with structured image reasoning prompts.

6.4 Geospatial Soil KNN Classifier & NPK Geocoding:
• Model Binary: `Backend/data/all_india_csv/soil_knn_model.pkl`
• Dataset: `india_district_soil_with_npk.csv`
• Algorithmic Workflow: Converts input latitude and longitude into radians. Uses a K-Nearest Neighbors
  classifier trained on Indian geographical coordinates to infer dominant soil types (Alluvial, Black,
  Red, Laterite, Desert, Mountainous) and estimated Nitrogen-Phosphorus-Potassium (NPK) ratios.
• Haversine Fallback: Computes great-circle distances across all district centroids in case of model anomaly.

6.5 Natural Language Processing (NLP) Rule & Template Pipeline (`nlp_service.py`):
• Intent Classification: Identifies 12 domain intents (CROP_RECOMMENDATION, DISEASE_DIAGNOSIS, PEST_MANAGEMENT,
  SOIL_MANAGEMENT, WEATHER_ADVICE, MARKET_INQUIRY, IRRIGATION_ADVICE, EQUIPMENT_HELP, GOVERNMENT_SCHEMES, etc.).
• Named Entity Recognition (NER): Extracts entities for Crop types, Diseases, Pests, Locations, Seasons,
  Quantities, and Time periods from natural user queries.

11. DEVELOPER AUDIT: CODE QUALITY, SECURITY & ARCHITECTURAL OBSERVATIONS
----------------------------------------------------------------------------------------------------
As a senior developer inspecting this codebase, here is an objective analysis of strengths, technical debt,
and critical recommendations:

STRENGTHS & HIGHLIGHTS:
1. Robust Multi-Model AI Orchestration: The intelligent fallback cascade (PyTorch CNN -> Gemini Flash -> Groq LLaMA 3.3)
   ensures zero downtime. If local PyTorch weights fail to load, cloud vision takes over seamlessly.
2. Comprehensive Feature Breadth: Spans the complete lifecycle of agriculture—from soil testing and crop
   selection to weather management, disease treatment, peer-to-peer selling, and aquaculture.
3. Clean Component Architecture: Excellent UI component modularity with Tailwind CSS and Radix primitives.
4. Mobile-Ready: Capacitor setup allows the web app to function as a native mobile APK with camera/GPS access.
5. Real-Time Capabilities: WebSocket integration for farmer community collaboration and live market schedulers.

CRITICAL OBSERVATIONS & SECURITY VULNERABILITIES:
1. API Keys & Secrets in Source:
   - In `Backend/app/core/config.py`, default API keys for OpenWeather and Gemini are committed in plaintext.
   - Recommendation: Remove all default fallbacks and enforce loading strictly from `.env` or secrets managers.
2. Duplicate Project Files:
   - Noticeable root files (`index.html`, `vite.config.ts`, `package.json`, `tailwind.config.ts`) exist in both the
     root directory and the `Frontend/` subdirectory.
   - Recommendation: Consolidate the repository structure into a clean Monorepo (`/frontend` and `/backend`)
     or move all frontend code to the root.
3. Authentication Synchronization:
   - `AuthContext.tsx` contains references to `localAuthService` (browser localStorage mock) alongside `authService.ts`
     (FastAPI JWT). In some offline modes, local storage is updated without verifying tokens with the backend.
   - Recommendation: Standardize on a single JWT authentication flow with automatic token refresh.
4. SQLite Concurrency in Production:
   - SQLite is used by default with `check_same_thread: False`. Under high concurrent user loads (e.g., simultaneous
     WebSocket connections or background schedulers writing prices), SQLite may experience database locks.
   - Recommendation: Switch to PostgreSQL (`psycopg2-binary` is already installed in requirements.txt).
5. Exception Handling & Logging:
   - Several services use broad `except Exception:` blocks that return fallback dictionaries without structured
     centralized error logging (e.g., Sentry).

12. STEP-BY-STEP PRODUCTION DEPLOYMENT & ROADMAP GUIDE
----------------------------------------------------------------------------------------------------
PHASE 1: PRE-FLIGHT ENVIRONMENT SETUP
1. Backend Setup:
   ```bash
   cd Backend
   python -m venv venv
   .\venv\Scripts\activate      # Windows
   pip install -r requirements.txt
   ```
2. Frontend Setup:
   ```bash
   cd ../Frontend
   npm install
   ```

PHASE 2: RUNNING LOCALLY
1. Terminal 1 (Backend):
   ```bash
   cd Backend
   uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```
   API Docs available at: http://localhost:8000/docs
2. Terminal 2 (Frontend):
   ```bash
   cd Frontend
   npm run dev
   ```
   Web App available at: http://localhost:8080

PHASE 3: PRODUCTION HARDENING ROADMAP
1. Database Migration:
   - Deploy a managed PostgreSQL instance (e.g., AWS RDS, Supabase, or GCP Cloud SQL).
   - Set `DATABASE_URL=postgresql://user:password@host:5432/farmiq` in `Backend/.env`.
   - Run Alembic migrations: `alembic upgrade head`.
2. Containerization (Docker Compose):
   - Create `Dockerfile` for Backend (Python 3.11-slim + PyTorch CPU/CUDA).
   - Create `Dockerfile` for Frontend (Node 20 build -> NGINX multi-stage image).
   - Compose with PostgreSQL and Redis (for WebSocket channel scaling).
3. CI/CD & Cloud Hosting:
   - Frontend: Deploy to Firebase Hosting, Vercel, or AWS CloudFront.
   - Backend: Deploy to AWS ECS, Google Cloud Run, or Kubernetes cluster.
4. Native Mobile Build:
   - Run `npm run build && npx cap sync android`.
   - Open Android Studio and generate signed release Android App Bundle (AAB) for Google Play Store.
